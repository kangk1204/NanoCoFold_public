# 연구실 GPU 한 대를 여러 자리에서 사용하기

**서버**는 NanoCoFold를 설치한 Ubuntu 컴퓨터입니다. **사용자 PC**는 브라우저를 여는 컴퓨터입니다. 서버에 한 번만 설치합니다. 연구원은 본인이 제출한 분석을 보고 관리자는 연구실 전체 결과를 봅니다.

## 서버 관리자

1. [기존 설치 업데이트](UPDATE.ko.md)를 마치세요. 다음 명령은 처음 설치한 소스 폴더에서 실행합니다.
2. 관리자 한 명을 등록하고 연구원마다 NanoCoFold 계정을 하나씩 만드세요. 계정 이름은 결과 표에 표시되는 담당자 이름입니다. 연구원 추가 명령에서 각 연구원의 비밀번호를 두 번 입력합니다.

   ```bash
   python3 scripts/lab_account.py init-admin
   python3 scripts/lab_account.py add 송윤진
   python3 scripts/lab_account.py add 김연구
   ```

3. 웹 서버를 한 번 시작하고 이 터미널을 열어 두세요.

   ```bash
   bash start.sh --no-browser --port 18765
   ```

서버에서 `init-admin`을 실행하면 일회용 활성화 코드가 표시됩니다. 첫 로그인에서 **admin / admin**을 입력한 뒤 그 코드와 새 관리자 비밀번호(10자 이상)를 입력하세요. 새 비밀번호로 다시 로그인하면 전체 결과가 열립니다. 활성화 전에 코드를 잃어버리면 서버에서 같은 명령을 다시 실행하세요. 이미 연구원이 `admin`이라는 이름을 사용했다면 서버 운영자가 계정 소유자를 확인한 후 `python3 scripts/lab_account.py promote-admin`으로 기존 계정을 승격할 수 있습니다.

**이후 비밀번호를 바꾸려면** 로그인 후 계정 이름 옆의 **비밀번호 변경**을 누르세요. 현재 비밀번호를 입력하고 새 비밀번호를 두 번 입력합니다. 변경 후에는 사용 중인 기기마다 다시 로그인하세요. 실행 중인 분석과 저장된 결과는 유지됩니다. 연구원도 같은 방법으로 본인 비밀번호를 바꿀 수 있습니다.

**결과 DB → 관리자 · 결과 열람 권한**에서 **모든 연구원에게 연구실 전체 결과 열람 허용**을 선택하고 **권한 저장**을 누르면 공유됩니다. 선택을 해제하고 저장하면 다음 조회와 다운로드부터 본인 제출분으로 돌아갑니다. 이미 전달된 파일은 수신자가 보관합니다. 이 설정은 NanoCoFold 웹에 적용됩니다. 서버 SSH 계정의 파일 읽기 권한은 서버 운영자가 별도로 관리합니다.

첫 계정을 만들면 이 작업 공간은 로그인 화면을 사용합니다. 기존 결과는 그대로 남으며, 예전 기록의 담당자 칸은 비어 있습니다. 서버에서 `python3 scripts/lab_account.py list`로 계정 목록을 확인하세요. 비밀번호를 잊었으면 서버 운영자가 `python3 scripts/lab_account.py password 이름`으로 재설정할 수 있습니다. 계정을 비활성화하려면 같은 스크립트에 `disable 이름`을 전달하세요. 비활성화한 이름은 다른 사람에게 다시 할당할 수 없고, 기존 사용 기록은 남습니다. 계정 DB는 서버를 실행하는 Ubuntu 계정의 `~/.config/nanocofold/labs/` 아래에 있습니다. 백업할 때 작업 공간과 이 폴더를 함께 보관하세요.

## 사용자 PC

1. 터미널을 열고 아래 명령의 `USER@SERVER`를 관리자가 알려준 **SSH 계정과 서버 주소**로 바꾸세요. 각 사용자는 자기 자리에서 한 번씩 연결합니다.

   ```bash
   ssh -N -o ExitOnForwardFailure=yes -L 18765:127.0.0.1:18765 USER@SERVER
   ```

2. 터미널을 열어 둔 채 브라우저로 **http://127.0.0.1:18765**를 엽니다. 자신의 **NanoCoFold 계정**으로 로그인하세요. 다른 컴퓨터에 NanoCoFold나 GPU를 설치할 필요는 없습니다.
3. **환경·설치 → 여러 자리에서 같은 서버 사용하기**에서도 접속 방법을 다시 볼 수 있습니다. **입력·실행**에서 작업을 제출합니다. 접수 후 이 탭을 다시 열면 **1/4 분석 목적**에서 시작합니다. 앞서 입력한 서열은 재사용할 수 있고, 검토와 공용 MSA 전송 동의는 다시 확인합니다. 작성 중 잠시 다른 탭을 봤다가 돌아오면 작성하던 단계가 유지됩니다.
4. **작업·로그**에서 진행 상태를 확인하세요. 여러 사람이 같은 GPU에 분석을 제출할 수 있습니다. 기존 분석과 함께 실행할 여유가 없으면 여유 메모리, 작업 예약량과 대기 사유를 표시합니다. GPU가 사용 가능해지면 자동으로 시작합니다. 대기 중에도 본인 작업을 취소할 수 있습니다.
5. **결과 DB → 후보 서열·구조**에서 표적이나 후보 ID를 입력해 검색하세요. 엔진과 적격 여부로 좁힌 뒤 지표의 열 제목을 눌러 정렬합니다. 연습 실행을 함께 보려면 **연습 결과 포함**을 선택하고 **검색**을 누르세요. 후보 ID를 누르면 서열과 3D 구조가, 분석명을 누르면 보고서가 열립니다. **검색 결과 전체 Excel 저장**으로 전체 검색 결과를 받습니다. **분석 목록 → 연구실 사용 기록**에는 취소·대기 및 재사용 제출도 표시됩니다.

**분석 실행**을 한 번 누르고 **작업·로그**에 접수될 때까지 기다리세요. 처음에는 모델 파일을 확인하느라 몇 분 걸릴 수 있습니다. 작업이 목록에 보이면 브라우저를 닫아도 분석은 계속됩니다.

## 서열 전송과 결과 보관

- **실행 조건 → MSA 준비 방식**이 **공용 MSA 서버**이면 해당 입력의 단백질 서열을 외부 서버로 보내 유사 서열을 검색합니다. 전송하려는 경우에만 동의하세요. **검증된 MSA 캐시 재사용**은 해당 서열의 저장된 정렬이, **등록된 로컬 MSA 검색**은 서버에 준비된 검색 DB가 필요합니다. Boltz-2도 선택한 MSA 설정을 따릅니다.
- DB는 요약과 파일 위치·해시를 저장합니다. 확인된 동일 결과를 재사용하면 결과 파일 한 벌을 여러 제출에서 가리킵니다. **결과 탐색 → 용량 정리**에서 보존 파일과 예상 절감량을 검토하고 확인하면 지표·서열·최종 구조를 남길 수 있습니다. 나중에 PAE·MSA를 다시 보거나 중간 단계부터 재개하려면 원본을 보관하세요. 자동 삭제는 없습니다.
- 실제 분석은 시작 직전, 재개할 때, 대기 후 다시 시도할 때 선택한 GPU의 메모리와 사용률을 확인합니다. 조건을 충족하면 이미 다른 분석이 실행 중이어도 시작합니다. 사용률이 90% 이상이거나 상태를 읽을 수 없으면 대기합니다. 약 10초마다 재확인하며 대기 시간은 계산 제한 시간에 포함되지 않습니다.
- 기본 작업 예약량은 6 GiB입니다. 장치 전체에는 10% 또는 1 GiB 중 큰 값을 여유분으로 남기며, 작은 GPU에서는 예약량을 나머지 용량으로 줄입니다. 예측을 막 시작한 다른 NanoCoFold 작업이 앞으로 쓸 예약량도 반영합니다. 예약량은 스케줄링 기준입니다. 실제 최대 사용량은 엔진과 서열 길이에 따라 달라집니다. 예를 들어 연구실 분석이 보통 10 GiB를 쓴다면 서버를 시작할 때 `NANOCOFOLD_GPU_JOB_MIB=10240 bash start.sh --no-browser --port 18765`로 작업당 예약량을 지정할 수 있습니다. 설치나 단독 점검 중인 GPU는 해당 작업이 끝난 뒤 사용합니다.

결과 DB의 검색창에는 후보 ID 또는 VHH 서열 일부(연속 3잔기 이상)를 입력할 수 있습니다. 담당자를 함께 지정한 뒤 일치 후보를 누르면 해당 서열과 예측 구조가 열립니다. 같은 서열은 DB에 한 번만 저장합니다.

## 공유 실행 정책

관리자는 전체 결과를 조회하고 공유 범위를 설정합니다. 취소·재개는 제출자만 할 수 있습니다. 새 분석의 자동 결과 재사용은 같은 담당자의 제출 안에서만 이루어집니다. 이전에 공유된 기록은 유지됩니다.

같은 계정에서 로그인 실패가 1분 동안 5회 누적되면 잠시 기다린 뒤 다시 시도하세요. GPU 상태를 120초 동안 읽지 못하면 작업이 실패 상태로 바뀌며, GPU 번호와 드라이버를 확인한 뒤 재개할 수 있습니다. 메모리 부족으로 대기하는 작업은 자동 재확인을 계속합니다.

GPU 예약량은 관리자가 정하는 실행 정책이며 최대 메모리 예측값이 아닙니다. 설치·GPU 점검은 다른 작업과 충돌하지 않도록 단독으로 실행합니다. 별도 로컬 MSA 검색 서비스의 공유 티켓은 분석 취소와 별개로 관리되므로, 공유 검색을 중단하려면 서버 운영자가 사용 중인 다른 요청을 먼저 확인해야 합니다.
